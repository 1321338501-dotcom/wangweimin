任务一 · 事件侦探

观测 · 记录 · 不写代码（在课程页第 3 节探针区操作）

操作记录

用手机（或 DevTools 设备模式）在事件探针区依次做 5 种操作，记录到的触发顺序如下：

操作记录到的触发顺序观察要点
① 单击touchstart → touchend → click没有 move；click 是系统在 touchend 后补发的
② 向上拖动touchstart → touchmove ×N → touchend → click拖得越远、越慢，move 次数越多
③ 向左快速滑touchstart → touchmove ×少量 → touchend → click速度快时 move 次数明显变少，但位移大
④ 双指触摸touchstart(touches=2) → touchmove ×N(touches=2) → touchend ×2每次 move 都能读到 2 个触点，抬手分两次触发
⑤ 长按后抬起touchstart → （静置 600ms，无新事件）→ touchend → click长按本身不是事件，要靠定时器自己判定

三个思考问题与答案

① 一次拖动里 touchmove 大约触发多少次？和距离有什么关系？
一次拖动能触发几十次 touchmove，具体次数取决于移动距离、移动时间与设备采样率。 距离越大、时间越长，次数越多；而同样距离下快速甩动，因为时间短，次数会比慢慢拖动少。 原因是浏览器每采样到一次手指位置变化就派发一次 move，并不是按"像素"派发，而是按采样周期派发。 这也是"跟手"的实现基础——move 越密，画面跟在手指后越平滑。
② click 出现在 touchend 之前还是之后？
之后。完整顺序是 touchstart → touchmove… → touchend → click。 click 是浏览器在 touchend 之后补发的一次"兼容事件"， 目的是让只写了 click 的老代码在移动端也能用。 所以如果 touch 和 click 两套逻辑都写，就会"点一次执行两次"—— 解决方式是二选一，或在 touch 处理里调用 preventDefault() 阻止后续 click。
③ 如果把 touchend 换成 touchcancel，会发生什么？
两者的触发时机不同：touchend 是手指正常抬起， touchcancel 是手势被系统打断（来电、消息横幅、手势返回、浏览器接管）。 如果只把收尾逻辑挂在 touchcancel 上，那么正常抬手时什么都不会执行： 滑动不切换、长按定时器不被清除、拖动状态一直留着，页面看起来像"卡住了"； 反过来，如果只监听 touchend 而不监听 touchcancel， 正常操作没问题，但被电话打断后状态同样会残留。 正确做法是两个事件都监听，并共用同一个收尾函数（清定时器、重置坐标、移除激活样式）。

任务二 · 手势卡片

手势识别 + DOM 操作（不需视频，发布后可直接看到）

效果说明：
  • 页面是一张「中华美食卡片」，共 4 道菜：北京烤鸭、麻婆豆腐、白切鸡、兰州牛肉面，每张带渐变背景与简介。
  • 左滑切下一道，右滑切上一道；底部实时显示「第 N / 4 张」，并有圆点指示当前页。
  • 横向位移小于 40px 视为误触，不切换；纵向位移大于横向时视为滚动页面，也不切换。
  • 切换带 0.3s 滑动过渡；快速连滑有 300ms 冷却锁，一次滑动只切一张，不会跳两张。
  • 在第一张继续右滑、最后一张继续左滑，底部弹出提示「已经是第一张了 / 已经是最后一张了」。
  • 卡片容器设 touch-action: pan-y：横向手势归脚本，纵向仍可正常滚动页面。

任务三 · 图片查看器

多指手势 · 变换 · 状态管理（含手机实体演示视频）

效果说明：
  • 打开页面提示「双指缩放请用手机打开」，图片居中铺满查看器。
  • 双指缩放 1x～4x，以两指中点为缩放基准，缩放时图片不会"跳走"。
  • 双击在 1x 与 2x 之间切换，带 0.25s 过渡，锚点是双击位置。
  • 放大后单指拖动查看细节，松手按边界夹紧；缩回 1x 自动居中、无法拖出边界。
  • 旋转屏幕或改变窗口后保留当前倍数，只重新计算边界并夹紧位移。
  • 右上角实时显示当前倍数，左下角提供「重置 1x」「放大 2x」按钮。
  • 保证"缩放不跳"的做法：比例变化时按 tx₁ = sx − (sx − tx₀) × (s₁ / s₀) 同步修正位移，让锚点下的图像内容保持不动。

任务四 · 摇一摇彩蛋

设备传感器 · 权限 · 降级（含手机实体演示视频）

效果说明：
  • 页面提示「摇一摇手机，抽今日菜谱」，下方是结果卡，初始显示占位「— — —」。
  • 监听 devicemotion，取 accelerationIncludingGravity 计算合成加速度。
  • 合成加速度超过阈值 18 判定为摇动，触发后进入 1.5 秒冷却，一次摇动只抽一次。
  • 随机抽取一道菜（8 道菜谱），带弹出动画与手机图标摇晃反馈；支持时还会调用振动。
  • iOS 13+ 先显示「允许使用传感器」按钮，点击后调用 DeviceMotionEvent.requestPermission() 授权。
  • 不支持传感器、没有权限或 1.2 秒内收不到数据时，显示「当前设备不支持，请用手机打开」，并提供「点我抽一次」按钮作为降级方案。
  • 为什么必须做降级：电脑没有加速度计、部分机型权限被关、浏览器可能不派发事件；不降级的话页面会永远没有反应，用户会以为坏了。

第 1 关 · 认识 JSON：数据的"通用快递箱"

对象 → 字符串 → 对象，三次挥手

数据要在"服务器"和"浏览器"之间来回跑，得说同一种话——这种话就是 JSON。它长得和 JS 对象几乎一样，但本质是字符串：发出去时把对象变成字符串，收回来时再变回对象。

📦 一句话记住：JSON 就是数据的"通用快递箱"。JSON.stringify 装箱，JSON.parse 拆箱。箱子里的规矩只有三条：键名加双引号、字符串加双引号、最后一项后面不加逗号。

// ① 数据的样子：一个数组，里面装着一堆对象
var wwm_poems = [
  { title: "短歌行", content: "对酒当歌，人生几何！" },
  { title: "雨晴", content: "雨前初见花间蕊。" }
];

// ② 装箱：对象 → JSON 字符串（服务器发数据时干的事）
var wwm_str = JSON.stringify(wwm_poems);
console.log(wwm_str); // [{"title":"短歌行",...}]

// ③ 拆箱：JSON 字符串 → 对象（浏览器收到数据时干的事）
var wwm_arr = JSON.parse(wwm_str);
console.log(wwm_arr[0].title); // 短歌行

🔍 怎么判断手里是"箱子"还是"东西"？typeof 一下：字符串会告诉你 string，对象会告诉你 object。搞混了就会报 undefined。

第 2 关 · 数据变页面：一条数据 = 一张卡片

createElement + 模板字符串 + appendChild

有了数据，下一步就是把它"画"到页面上。套路只有三步：建元素 → 塞内容 → 挂到页面。数据有几条，就循环几遍；所以只要改数据，页面自动跟着变——这就是"数据驱动页面"的起点。

// 数据（本关先用"写死在页面里"的数组，第 4 关再换成从服务器取）
var json = [
  { pic: "图片地址", title: "标题", content: "这里是内容" }
];

var wwmList = document.querySelector(".wwm-grid");
for (var v of json) {
  var li = document.createElement("div");     // ① 建元素
  li.className = "wwm-card";
  li.innerHTML = `
    <img src="${v.pic}" alt="">
    <div class="wwm-card-body">
      <h3>${v.title}</h3>
      <p>${v.content}</p>
    </div>`;                                    // ② 塞内容（反引号模板 + ${}）
  wwmList.appendChild(li);                      // ③ 挂到页面
}

💡 模板字符串的两个要点：反引号 `` ` `` 包起来的内容可以换行；${ } 里能直接写变量和表达式。

第 3 关 · 启动本地数据服务：让数据有个"门牌号"

项目\db\db.json → localhost:3004/api/poems

直接把 db.json 双击打开，只是"看见"了数据；网页里的 JS 读不到本地文件。我们要在本机用 Express 开一台小型服务器，把数据通过一个网址（接口）发出去。

名词餐厅里对应什么在你项目里是什么
服务器后厨：一直在上班，随时能出菜node server.js 跑起来的程序
接口取餐窗口：窗口号就是地址http://localhost:3004/api/poems
路由窗口上挂的菜单app.get('/api/poems', ...)

🍜 串成一句话：浏览器（顾客）照着窗口号 fetch 点单 → 服务器（后厨）按路由找到对应窗口 → 把 db.json 里的数据端出来（res.json）→ 浏览器 .json() 拆开"开吃"并渲染。

const express = require('express');
const fs = require('fs');
const path = require('path');

const app = express();
const wwm_port = 3004;

// ① 定义一个 GET 接口：/api/poems
app.get('/api/poems', (req, res) => {
  // ② 读 db.json（字符串）→ JSON.parse 转对象
  const wwm_data = JSON.parse(
    fs.readFileSync(path.join(__dirname, 'db.json'), 'utf-8')
  );
  // ③ 允许跨域
  res.set('Access-Control-Allow-Origin', '*');
  // ④ res.json() 自动 JSON.stringify + 设置 Content-Type
  res.json(wwm_data.poems);
});

app.listen(wwm_port, () => {
  console.log(`数据服务器已启动：http://localhost:${wwm_port}/api/poems`);
});

第 4 关 · fetch 取数据：把服务器"喊"过来

fetch → .json() → 渲染（then 链 / async await）

fetch() 是浏览器自带的网络请求函数。它发出请求后不会立刻给你数据，而是先给你一个"承诺"（Promise），数据回来了再去处理——所以要用 .then() 接，或者用 await 等。

🔗 一句话理清前后端分工：服务器用 res.json(对象) 把数据"发出去"；浏览器用 fetch().then(r => r.json()) 把数据"收回来并解析"。一进一出，正好各一次 JSON 转换。

// ── 写法 A：then 链 ──
var wwm_api = 'http://localhost:3004/api/poems';

function wwm_loadPoems() {
  fetch(wwm_api)
    .then(function (wwm_res) { return wwm_res.json(); })   // 第一次：响应头
    .then(function (wwm_poems) { wwm_renderPoems(wwm_poems); }) // 第二次：响应体
    .catch(function () {
      document.getElementById('wwm_poemList').innerHTML =
        '数据获取失败！请先在 db 文件夹运行 node server.js（端口 3004）';
    });
}

// ── 写法 B：async / await（更接近"同步"思维，推荐）──
async function wwm_loadPoems2() {
  try {
    const wwm_resp = await fetch('http://localhost:3004/api/poems');
    const wwm_poems = await wwm_resp.json();
    wwm_renderPoems(wwm_poems);
  } catch (err) { console.log('请求失败：', err); }
}

🔑 为什么是两次 .then？第一次等到的是"快递到了门口"（响应头），第二次 wwm_res.json() 才是"拆开包裹拿东西"（响应体）。

第 5 关 · 报错排雷：6 类高频错误对照表

先看报错，再改代码

你看到的报错真正的原因怎么修
ERR_CONNECTION_REFUSED服务器没启动，或端口不是 3004在 db 文件夹执行 node server.js；端口被占用就改 wwm_port
404 Not Found接口路径写错浏览器打开 http://localhost:3004/api/poems 验证，路径必须和 app.get 一字不差
Cannot find module 'express'没装依赖，或终端不在 db 文件夹进入 db 文件夹执行 npm init -y 再 npm install express
blocked by CORS policy服务器没给"跨域通行证"加 res.setHeader('Access-Control-Allow-Origin','*')
Unexpected token '<', ... is not valid JSON请求回来的是 HTML（404 页面），不是 JSON先 console.log(await resp.text()) 看拿到了什么
Cannot read properties of undefined字段名对不上（数据叫 pic，代码写了 img）打开接口地址核对字段名，console.log(res[0]) 先看清结构

🧭 调试固定动作：F12 → Network 看请求状态码；F12 → Console 看红色报错。90% 的问题在这两处能直接看出来。

答辩四问：
① 为什么 fetch 要写两个 then？—— 第一个 then 拿到的是"响应对象"（快递到门口），第二个 res.json() 才是"拆开包裹拿数据"（解析响应体）。
② .json() 之前拿到的是什么？—— 是 Response 对象，包含状态码、响应头等元信息，还不是数据本身。
③ CORS 是谁拦的？—— 是浏览器拦的。服务器没返回 Access-Control-Allow-Origin 头时，浏览器出于安全策略阻止 JS 读取响应。
④ 如果服务器没启动，页面表现如何？—— fetch 会 reject，进入 catch 分支，显示友好提示而不是白屏。
